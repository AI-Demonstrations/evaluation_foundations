# Golden Dataset — Provenance and Review

`golden.jsonl` holds 60 labeled support tickets for a ticket-routing system with four
queues: `billing`, `technical`, `account`, `shipping` (15 each). Both examples in this
project evaluate against this one file.

> **Teaching example.** The tickets were generated by an AI tool and the reviewer fields
> are illustrative, to show the format your team's dataset should take. In your project,
> every example and label must be reviewed by a real team member.

## Fields

| Field | Meaning |
|---|---|
| `id` | Stable example ID (`g001`…) — never renumber; reports refer to it |
| `text` | The ticket as the customer wrote it |
| `label` | The final, accepted label (the ground truth the harness scores against) |
| `channel` | `email` or `chat` — a slice, so you can check the model works on both |
| `source` | Where the example came from (here: `generated:claude-opus-5-5`) |
| `reviewer_a` | Label from the first reviewer (every example) |
| `reviewer_b` | Label from the independent second reviewer (20 examples; `null` otherwise) |
| `adjudication` | How a disagreement between reviewers was resolved |

## Generation prompt

> Write 15 short customer-support tickets for each of four queues — billing, technical,
> account, shipping — as a customer would type them. Include a few that plausibly belong
> to two queues (e.g. a checkout page that freezes), and avoid reusing the same keywords
> in every ticket of a queue.

## Review rubric

A ticket's label is **the team that can resolve it without handing it on**:

- **billing** — money moved or should have: charges, refunds, invoices, payment methods, discounts
- **technical** — the product misbehaves: errors, crashes, broken features, performance
- **account** — identity and access: sign-in, passwords, profile, ownership, personal data
- **shipping** — physical delivery: tracking, addresses, damage, missing items, returns logistics

When a ticket fits two queues, pick the queue that owns the **root cause**.

## Agreement

Reviewer B independently labeled 20 examples (5 per class). Run
`python 02_ml/review_agreement.py` to compute raw agreement and Cohen's kappa. The 4
disagreements were resolved by discussion against the rubric; each resolution is in the
`adjudication` field.
